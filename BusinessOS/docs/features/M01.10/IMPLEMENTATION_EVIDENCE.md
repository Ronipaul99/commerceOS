# M01.10 implementation evidence

| Area | Delivery |
|---|---|
| Requirement and risk | Master §§16.6 and 21, especially 21.3. Standard-risk diagnostics on existing authorized commands. Human review and milestone release gates are pending. [Design](DESIGN.md) |
| API and health | HTTP spans observe final status, latency, errors and disconnects. The existing `/health` and `/ready` paths retain their responses. DB, Redis and storage checks record fixed diagnostic outcomes. Untrusted headers, URLs, bodies and raw errors do not enter telemetry. [HTTP instrumentation](../../../apps/api/src/observability.ts) · [Readiness](../../../apps/api/src/health.controller.ts) |
| PostgreSQL and outbox | The existing transaction writes nullable, server-generated `trace_parent` with the event. The worker reads it from the authorized row after the signed job and scope checks. During rollout older writers can omit the field and older consumers can continue. No FK, tenant constraint, event payload or queue reference changed. [Migration](../../../packages/database/fixtures/migrations/20261125000100_outbox_trace_parent/migration.sql) · [Outbox write](../../../apps/worker/src/outbox/store.ts) · [Consumer](../../../apps/worker/src/outbox/consume.ts) |
| Redis and jobs | Outbox and file queue checks measure counts and failed operations. BullMQ stalled and failed events produce distinct coded signals. Outbox age is measured on claim and dead letters get their own signal. Queue event arguments, failed reasons and job identifiers stay out of logs. [Outbox broker](../../../apps/worker/src/outbox/bull.ts) · [File runtime](../../../apps/worker/src/files/runtime.ts) |
| Data and signals | OpenTelemetry API, trace SDK and metrics SDK are pinned. The local trace buffer retains 256 completions per instance. The label sets are fixed. Diagnostic records contain random internal trace/span IDs and, only for trusted scope, process-keyed actor and tenant references. Raw IDs, SQL, exceptions, auth and business data are absent. Failed diagnostic sinks cannot change a command or job. [Telemetry package](../../../packages/telemetry/src/index.ts) · [OpenTelemetry instrumentation](https://opentelemetry.io/docs/languages/js/instrumentation/) |
| Dashboard and alert routing | The local CLI reads a bounded log sample and shows aggregate timings/counts or a single causal trace. Alerts have coded triggers and role ownership. A collector/exporter, live pager, retention, pool metrics in hosted environments and approved numeric thresholds require live operational decisions. [Operator report](../../../scripts/telemetry/report.mjs) · [Runbook and SLO proposals](RUNBOOK.md) |
| API/UI/events impact | No public API or generated client change, new user-facing UI, changed domain event or tenant entitlement. The integration route exists only in the native test. |
| Build and rollback | The local API image includes only the new workspace dependency. Apply the nullable expand migration first. Restore the previous API and worker images on rollback and keep the added column. [API image](../../../infra/local/api.Dockerfile) · [Rollback](RUNBOOK.md#rollback) |
| Evidence and review | Native and local acceptance evidence is recorded separately. G-11, G-12, hosted collector/exporter, on-call roster and actual M01 platform acceptance remain pending. [Verification](VERIFICATION.md) |
